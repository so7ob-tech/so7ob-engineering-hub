# Research source policy

For repository identity, features, license, technical stack, configuration, and deployment behavior, prefer the canonical repository, official documentation, release notes, and source files. For maintenance, use commit/release history and maintainer statements. For known vulnerabilities, consult official security advisories and trusted vulnerability databases, recording the affected versions and check date. Independent technical reviews may add context but should not replace primary evidence.

Store one source record per material claim with `url`, `source_type`, `checked_at`, `claim`, and `confidence`. Preserve disagreements between sources as unresolved rather than choosing a convenient answer. Do not report a link as verified merely because it was found in a search result. Commercial product sites belong in `product-references/` and are not source-reuse candidates.
