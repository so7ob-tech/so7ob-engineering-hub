**Finding (checked 2026-10-14): Dolibarr is a live, modular PHP ERP/CRM with substantial native SMB business coverage and a cleanly stated GPL-3.0-or-later core, making it a credible candidate for evaluation—not an unconditional adoption.** It covers finance, purchasing, stock and entry-level MRP/BOM workflows, and HR administration, but payroll is explicitly not supported and no evidence establishes deep manufacturing planning, Arabic RTL correctness, or any regulatory certification. [1] [2] [3]

- **Exact repository:** https://github.com/Dolibarr/dolibarr; canonical product site: https://www.dolibarr.org/. Product class: SMB ERP/CRM suite with modular business applications. The canonical repository identifies the PHP/JavaScript ERP/CRM, standalone and web use, and the GPL license. [1]
- **Domain fit by module:** User documentation identifies the following as standard modules available in common installations; they are activated selectively, not a single mandatory uniform feature set. Finance includes customer/supplier invoices and credits, payments, banks/cash, SEPA payment files, margins, simplified accounting and double-entry accounting with general/subsidiary ledgers and accounting exports. Purchasing includes vendors, supplier price requests, purchase orders, reception, supplier invoices and Incoterms. Inventory includes products/services, stock, lots/serials, variants, BOM, manufacturing orders and workstations. HR includes users/employees, leave, expenses, recruitment and HRM/employee contracts. [1] [2]
- **Depth and boundaries:** Official product documentation describes BOM components/consumption, manufacturing orders built from BOMs, one-or-multiple-step production, automatic stock increments/decrements, virtual stock including open orders, and lot traceability. This supports basic MRP/manufacturing workflows, not evidence of advanced finite-capacity scheduling or full-scale production execution. Payroll is explicitly listed as not fully supported; employee salaries/payment recording is not payroll processing. The “Accounting (simplified)” module expressly has no ledger table; double-entry is a separate module. Assets are marked in development, dynamic prices experimental, advanced stock transfer in development, and Zapier in development. Multi-company requires an external module. External modules/plugins and third-party marketplace products must not be counted as core coverage. [1] [2] [3] [4]
- **Edition and license boundary:** Repository COPYING contains GNU GPL version 3, and repository describes GPL-3+ (version 3 or any later version); repository also warns that included dependencies have other licenses and points to COPYRIGHT. Dolibarr is not presented as a proprietary Enterprise-only core in the reviewed sources. Paid hosting, partner services and marketplace modules are separate commercial offerings; official DoliStore explicitly lists both free and paid add-ons. Review dependency and add-on licenses individually and obtain legal review for intended modification, distribution or network delivery; a public repository is not itself commercial-use clearance. [1] [5] [6]
- **Current release and maintenance:** Repository release page showed 24.0.1 as the latest release, with 24.0.0 changelog and a 24.0.1 fix list, including security-relevant permission fixes and ordinary defect corrections; official homepage announced v24. Recent release evidence, not stars, supports active maintenance. A precise supported-branch policy or commit cadence was not independently established in this review. [7] [8]
- **Security and dependencies:** A maintained security policy exists, but the project says it does not use GitHub Security Advisories, reports vulnerabilities via GitHub issues or security email, and processes reports around monthly. Scope is limited to recent stable versions/develop and default stable modules; experimental/development/external modules are excluded. Its stated production baseline requires HTTPS, production mode, CSRF protection, read-only code tree, documents outside web root, restricted write access and rate limiting (Fail2ban rules). This is meaningful operational guidance, not assurance that a deployment is secure. Repository says some bundled dependencies use other licenses; a full current dependency/SBOM vulnerability audit and advisory reconciliation were not established here. No security certification or assurance is implied. [9] [1]
- **Architecture and deployment:** Core is PHP with JavaScript enhancements and described as using no heavy framework, with modules, hooks and triggers as extension points. It supports Apache/Nginx, PHP and MySQL/MariaDB or PostgreSQL per repository overview; upstream also provides Docker instructions and packaged options. On-premise deployment is supported alongside third-party/partner cloud hosting; cloud convenience features such as provider-managed upgrades/backups/support are hosted-provider services, not inherent edition-exclusive core features. Production operations still require database/web-server administration, secure file permissions, backups and upgrade planning. [1] [10] [11]
- **Documentation and testing:** Official wiki documents user modules, installation/upgrade and REST API usage. A repository test directory describes PHPUnit unit tests and quality-analysis tooling. This establishes documented tests, not a verified current CI pass, coverage level or complete end-to-end validation; no test run was performed for this assessment. [2] [10] [12]
- **Integrations and APIs:** REST server is a documented module with an API explorer/Swagger description, API-key header authentication and GET/POST/PUT/DELETE operations. SOAP is described as deprecated. Webhooks, LDAP, OAuth, payment providers, email/IMAP and calendar formats are documented among available integrations; availability varies by enabled module and some integrations (including Zapier) are marked in development. [1] [2] [13]
- **Arabic, i18n and RTL:** Arabic Saudi Arabia locale directory `htdocs/langs/ar_SA` exists and contains numerous language files, including accounting, HRM, manufacturing (`mrp`), stock and core UI resources. The translator documentation warns that non-English completeness depends on contributors and may be slightly or highly incomplete. This verifies Arabic translation-file presence, not actual translation completeness or that text is rendered correctly. The checked official/repository evidence did not establish right-to-left layout behavior; RTL must be tested in browser screens, PDF/ODT outputs, forms and third-party modules before Arabic deployment. Do not infer RTL from locale files. [14] [15]
- **Risks and gates:** Key due-diligence items are Arabic RTL validation, jurisdiction-specific accounting/tax workflow validation, scope acceptance for payroll and manufacturing, audit of third-party modules/dependencies, production hardening, and legal review of GPL/dependency/add-on obligations. Finance/accounting deployment requires specialist jurisdiction review; neither feature claims nor public source establish compliance or certification. [2] [9] [1]
- **Rubric scores (raw points, maxima in rubric order):** feature completeness/domain fit 16/20; architecture/reuse 12/15; maintenance 13/15; security/dependencies 9/15; documentation/tests 8/10; license clarity/suitability 8/10; setup/deployment 4/5; integrations/APIs 4/5; Arabic/i18n/RTL 2/5. **Midpoint 76/100; plausible range 65–85.** Range reflects unknown current test/CI execution, dependency/security posture, localization completeness/RTL, and task-specific fit; unknown evidence was not treated as zero.
- **Conditional recommendation:** `evaluate`, **medium confidence**. Advance to a bounded proof of concept only if target finance/accounting and manufacturing workflows pass, Arabic RTL is demonstrated where needed, security/dependency and third-party addon review is complete, and counsel approves the planned GPL/dependency use. Reassess security and release status before implementation; do not interpret this evaluation as production approval.
