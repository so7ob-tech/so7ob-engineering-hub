ERPNext is the strongest broad-suite candidate in this set for controlled evaluation: its native finance, purchasing, stock, replenishment, warehouse, manufacturing, quality and WIP scope is documented, while expanded HCM is better treated as a separate Frappe HR assessment.[1] [2] [3] It is **77/100 midpoint (57–87), medium confidence; evaluate**, not approved for adoption. The score is provisional and class-sensitive. Frappe REST endpoints, whitelisted methods and OAuth/token authentication are documented, but connector maintenance and terms must be checked individually.[4] The stack is Python/JavaScript with Vue-based UI and official container/deployment material; the disposable quick-start is not production architecture, so database/cache/runtime operations, migrations, backups and monitoring need a rehearsal.[5] GPL-3.0 is identified for ERPNext, while the pricing page contains conflicting AGPL wording; counsel must resolve the component/service boundary and trademark implications before reuse.[6] [7] Security reporting exists, but this review did not establish an audit, advisory disposition or clean dependency chain.[8] Arabic translation extraction is documented, **not Arabic completeness or RTL/bidi behavior**; acceptance-test Arabic UI, reports, print formats and mixed Arabic/Latin content. Evidence note: [ERPNext review](../../research-sources/erp-candidates/01-erpnext.md).

## Integrated modular suites

**Odoo Community** is a viable open-core foundation when the target scope is mapped to exact modules and edition. Community first-party modules substantiate invoicing/accounting baseline, purchasing, inventory/warehouse and manufacturing; HR-related modules exist, but the supplied evidence does not establish Community payroll or country-specific statutory parity.[9] [10] It is **75/100 (62–84), medium confidence; evaluate**. Odoo 19 documents JSON-2, but external API access is restricted to Custom plans and XML-RPC/JSON-RPC are scheduled for removal in Odoo 22, making plan and migration constraints material.[11] The repository and inspected manifests identify LGPL-3, while Enterprise add-ons, third-party dependencies, hosted plans and API access have separate boundaries; public source is not blanket commercial clearance.[12] [13] Source installation leaves the operator responsible for PostgreSQL, application, TLS, upgrades and backups; the docs warn that pip installation can create security or dependency problems.[14] Arabic locale/language selection evidence does not prove translation completeness or RTL; test core screens, reports, documents and custom modules. Evidence note: [Odoo Community review](../../research-sources/erp-candidates/02-odoo-community.md).

**Dolibarr** offers a practical SMB ERP/CRM shape with native invoicing and payments, banking, procurement, stock/lots/serials, BOM/manufacturing orders, employee/leave/expenses/recruitment and HRM. Payroll is explicitly unsupported, simplified accounting has limitations, advanced finite-capacity planning is not established, and multi-company requires an external module.[15] It is **76/100 (65–85), medium confidence; evaluate**. REST with per-user API keys and webhooks/LDAP/OAuth/payment/email interfaces are documented, but availability is module-dependent and SOAP is deprecated.[16] Core is GPL-3+, with dependencies under other terms; paid hosting and marketplace add-ons are distinct from core and need license review.[17] The project has a security policy and production controls, but reporting is routed outside GitHub Security Advisories and the review did not establish a current SBOM or advisory reconciliation.[18] The ar_SA locale proves locale resources only; translation completeness and RTL visual behavior remain unverified across UI, PDF/ODT and modules. Evidence note: [Dolibarr review](../../research-sources/erp-candidates/03-dolibarr.md).

**Tryton** is a modular business platform with strong accounting, procurement, operations/inventory and manufacturing coverage through selectable modules. Attendance and Timesheet do not establish full HCM/payroll, and country-specific accounting/extensions require proof.[19] It is **74/100 (65–82), medium confidence; evaluate**. RPC and REST clients are documented, but maintained So7ob/local-provider connectors are unverified.[20] The repository metadata has a null license field; module-level LICENSE files make component-by-component legal review mandatory. Official translation architecture does not establish Arabic completeness or RTL; test end-to-end. Recent security notices include fixed template-injection and report-rendering/local-file concerns, while no GitHub SECURITY.md or published advisories were detected; pin patched versions and inspect templates/dependencies.[21] Setup requires a virtual environment, dependencies and module linking, so deployment reproducibility should be tested. Evidence note: [Tryton review](../../research-sources/erp-candidates/04-tryton.md).

## Distribution, manufacturing and operational fit

**metasfresh** is especially relevant for distribution, wholesale, inventory, manufacturing and finance: official functional documentation lists purchasing, warehousing, manufacturing (including BOM/MRP II), accounting/billing, logistics, payments and quality.[22] It is **59/100 (43–73), medium confidence; evaluate**. The REST API, EDI/SEPA references and Shopware/RabbitMQ history merit an integration POC, not an assumption of stable connectors.[23] The GitHub license endpoint returned no license and no root LICENSE was exposed; obtain the applicable grant and third-party notices before any commercial or network deployment.[24] The latest formal repository release is 5.175 from 2023-06-27 despite later commits, and no SECURITY.md or independent dependency/SBOM review was established.[25] Arabic and RTL are unknown; test UI, reports, REST payload workflows and mixed-direction output. Evidence note: [metasfresh review](../../research-sources/erp-candidates/08-metasfresh.md).

**Apache OFBiz** has broad documented finance, billing, purchasing, warehouses, lot/serialized stock, BOM/routings/MRP/costing and HR recruiting/positions/reviews/contracts/training scope. Ecommerce is in a complementary plugins repository and is explicitly not production-ready; plugin maturity varies.[26] It is **70/100 (57–79), medium confidence; evaluate**. REST service definitions, generated OpenAPI and JWT-secured endpoints are documented, but turnkey external connector status is not established.[27] The framework is Apache-2.0, but plugins/dependencies/notices still require review; no paid Enterprise matrix was verified.[28] The 24.09 branch is feature-frozen and receives fixes; 24.09.06/.07 patched 2026 vulnerabilities, and the project assigns deployers responsibility for host, extensions, integrations, credentials, exposure and logs.[29] Default/demo configuration is not production. Arabic/RTL is unknown, and Java/Tomcat production hardening and deployment configuration require a deliberate rehearsal. Evidence note: [Apache OFBiz review](../../research-sources/erp-candidates/05-apache-ofbiz.md).

**Axelor Open Suite** has source modules for finance, purchase, stock, production, supply chain and human resources, but those modules are not a uniform promise across editions or commercial features.[30] It is **72/100 (58–82), medium confidence; evaluate**. The current identified repository is `axelor/axelor-open-suite`; the originally declared `axelor/open-suite` URL does not exist, a material identity issue to record.[31] The source LICENSE identifies AGPLv3, while Pro and Enterprise editions are separately commercial; edition-by-edition feature and license confirmation is required.[32] Latest release evidence is v9.1.9 (2026-10-01), but no vulnerability scan, SBOM, audit or certification was performed.[33] Java/Gradle and webapp/submodule coordination make runtime and build reproducibility a gate. Multilingual infrastructure and English/French resources do not prove Arabic or RTL; test forms, reports and extensions. Evidence note: [Axelor Open Suite review](../../research-sources/erp-candidates/09-axelor-open-suite.md).

## Legacy, limited or reference-oriented projects

**iDempiere** has a strong accounting foundation and modular Java/OSGi architecture, but current first-party evidence does not establish comprehensive core manufacturing, HCM, Arabic or RTL coverage. Procurement and supply-chain fit should be demonstrated module by module.[34] It is **68/100 (58–78), medium confidence; evaluate**. REST Web Services are documented as a separately maintained GPLv2 extension, not proof that all APIs are core-bundled.[35] The repository is GPLv2 with no distinct Enterprise matrix verified. Release-13 and master are marked supported, but the review found no packaged GitHub release and did not establish a current dependency scan/SBOM or advisory inventory; pin a supported branch and assess security before deployment.[36] Evidence note: [iDempiere review](../../research-sources/erp-candidates/06-idempiere.md).

**ADempiere** is a genuine broad ERP/CRM/manufacturing/supply-chain suite with finance, procurement, inventory/warehouse, production and HR/payroll components. Its **58/100 midpoint (46–70), medium confidence; reference_only** status reflects evidence, not a claim that the software is unusable. The latest verified published release is 3.9.4.001 from 2023-12-20; a later develop push does not establish current release readiness or support policy.[37] GPL-2.0 applies, while security policy/advisory state was not established; historical Log4j updates do not establish current safety, so require a present SBOM, scan, patch and response-owner review.[38] Web services and OIDC/S3/notification references need current protocol and connector validation. Arabic translation/RTL and jurisdiction-specific finance/payroll remain gates. Evidence note: [ADempiere review](../../research-sources/erp-candidates/07-adempiere.md).

**webERP** covers finance/accounting, procurement, inventory/warehouse and manufacturing-related workflows, but advanced production scheduling/MES and expansive HR claims are not established in the reviewed manual; webSHOP and CounterLogicPOS are separate add-ons.[39] It is **61/100 (48–72), medium confidence; evaluate** only after source/release reconciliation. The official website calls v5.0.1 current, while the canonical repository README identifies v4.15.2 as stable/current RC, GitHub releases are empty and visible commits stop at 2025-07-05.[40] GPL-2.0-only and bundled dependencies require legal and dependency review; no project SECURITY.md surfaced.[41] The API evidence is an API tutorial/EDI plus phpxmlrpc, not proof of a modern REST connector ecosystem. Arabic claims are limited to 37-language/UTF-8 statements; RTL and PDF/report behavior require hands-on tests. Evidence note: [webERP review](../../research-sources/erp-candidates/10-weberp.md).

## Decision use and evidence limits

For So7ob’s likely finance, procurement, operations, manufacturing and localization needs, the most useful first POC set is **ERPNext, Odoo Community, Dolibarr, Tryton and metasfresh**, with **Apache OFBiz or Axelor** as architecture/edition alternatives. This is a fit-oriented shortlist, not a universal ranking: integrated suites score differently from distribution-focused or limited/reference projects, and each score is provisional, class-sensitive and bounded by the supplied evidence. iDempiere, ADempiere and webERP are better treated as conditional or reference candidates until release provenance, security posture, module maturity and Arabic/RTL are demonstrated.

All ten supplied reviews were successful; there are no review failures to disclose. No score, source repository, active status, release, or public availability implies adoption approval, production readiness, security assurance, certification, legal clearance or commercial reuse authorization. Required gates across the set are: scoped workflow POC; jurisdiction-specific finance/payroll validation; Arabic native-speaker and visual RTL/bidi acceptance tests; pinned supported versions; dependency/SBOM and vulnerability review; backup/restore and upgrade rehearsal; and license/edition/component review.
