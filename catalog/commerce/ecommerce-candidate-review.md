# E-commerce Candidate Review

> **Provisional screening comparison only.** This report synthesizes the supplied candidate-level research for So7ob Tech. It compares unlike architectures and does **not** constitute a definitive market ranking, production-readiness assessment, security audit, compliance review, scalability assessment, or full Arabic/RTL conclusion.

**Evidence cut-off:** supplied research checked **2026-10-14** unless a candidate-specific date is stated. Scores below are provisional rubric-based screening scores, not an independent benchmark. During integration, totals were recalculated as the sum of the nine stated criterion points; Sylius, PrestaShop and Bagisto totals were corrected where the original totals did not match their breakdowns.

## Executive synthesis

### Main conclusions

- **Headless/API-first evaluation:** Saleor, Medusa, Vendure, Sylius, Spree, Magento Open Source, PrestaShop, Shopware, Bagisto and WooCommerce all have some supplied evidence of APIs or headless capability, but the evidence differs substantially. Saleor is explicitly GraphQL-only/API-only; Medusa is an API-consuming platform with REST routes; Vendure exposes separate Shop and Admin GraphQL APIs; Sylius, Spree, Magento and PrestaShop document REST/API surfaces; Shopware, Bagisto and WooCommerce document API-first or REST capabilities. Headless capability does **not** establish a hosted service, managed SLA, turnkey storefront, or low operational burden.
- **Strongest customizable/self-hosted framework candidates:** Medusa, Vendure, Sylius, Saleor, Spree and Bagisto are the clearest framework/platform-style options in the supplied evidence. They offer extension points, APIs and separate or replaceable clients, but require validation of operational complexity, supported versions, dependency posture and So7ob workflows.
- **Traditional plugin fit:** WooCommerce is the clearest plugin-first option because it is WordPress-coupled. Its conventional deployment may be attractive where WordPress is already the operating context, but it is less aligned with an independently deployed commerce service unless the required headless/API approach is proven. Its multi-vendor capability is documented as a **separate plugin**, not core evidence.
- **Marketplace fit:** Spree and Bagisto have the strongest supplied evidence of marketplace primitives in the open-source offering. Spree documents seller onboarding, order splitting, commissions and a payout ledger; Bagisto documents seller management, commissions, product approvals, order handling and a vendor dashboard. Medusa and Vendure identify marketplaces as use cases, but the supplied evidence does not establish complete native seller tenancy, onboarding, permissions, commissions or payouts. WooCommerce points to a separately installed marketplace plugin. For the remaining candidates, multi-vendor capability is unknown or not evidenced.
- **Arabic/RTL:** Arabic/RTL remains a gating validation item for nearly every candidate. Bagisto has the strongest supplied signal: the 2.5 branch lists `ar` among locales and official localization documentation explicitly identifies RTL support for Arabic, Hebrew and other RTL languages. This still does **not** verify complete Arabic translations or correct RTL behavior across all storefront, admin, themes and extensions. All other candidates remain unknown or limited to generic localization/translation evidence.
- **License diligence is material:** MIT/BSD candidates are comparatively clear at the repository boundary, but dependencies, extensions, plugins, trademarks and paid/enterprise components require separate review. Vendure's repository states GPLv3 and discusses a plugin exception and commercial Platform; Magento's OSL-3.0 has external-deployment and ordering-document qualifications; PrestaShop uses OSL-3.0 for Core and AFL-3.0 for Modules; WooCommerce's readme says GPLv3 while the root license could not be retrieved and GitHub metadata says `NOASSERTION`.
- **Security requires exact-version verification:** Every candidate has some security-process or advisory evidence, and several have material 2025–2026 advisories. Before any selection, map the intended release to the candidate's fixed versions and supported-version policy, then inspect transitive dependencies. No supplied evidence supports declaring any candidate secure or audited.

## Fit by use case

### 1. Hosted/headless use cases

The supplied evidence supports a **headless architecture comparison**, not a hosted-vendor comparison. Only Medusa's documentation is reported to offer Medusa Cloud as a managed alternative; no supplied finding establishes its SLA, regional availability, compliance, performance or suitability for So7ob. Saleor's repository describes a separate API-only backend, dashboard and storefront projects, and Docker deployment. That is a strong composable architecture signal but also implies integration and operations work.

**Most relevant to investigate first:**

1. **Saleor** — strongest explicit GraphQL-only/API-only evidence; webhooks, apps, metadata, attributes and API extensions. Multi-vendor and Arabic/RTL are unverified; database and test status were not verified.
2. **Medusa** — REST API routes, modules, workflows, provider integrations, custom modules and a separate optional Next.js storefront; PostgreSQL is the core datastore. Marketplace is a stated use case, not a verified turnkey seller solution.
3. **Vendure** — separate Shop/Admin GraphQL APIs, background worker and plugin extension model. Strong framework fit, but current security advisories and GPLv3/licensing review require attention.
4. **Sylius** — Symfony/API Platform REST positioning with replaceable frontend and channels/locales. Strong for bespoke engineering, not a turnkey hosted service.
5. **Spree** — REST Store/Admin/Seller APIs, SDKs, optional Next.js storefront and explicit marketplace primitives. Database and Arabic/RTL remain unknown.
6. **Bagisto** — REST API package with admin/shop surfaces, Sanctum and Swagger, plus GraphQL reference; multi-vendor and RTL signals are comparatively strong, but the latest supplied release is a beta (`v2.5.0-beta2`).

**Also viable for headless evaluation, with heavier or more traditional application constraints:** Shopware, Magento Open Source, PrestaShop and WooCommerce all document APIs/headless capability, but their supplied evidence points to larger monolithic or host-application ecosystems and more substantial version, extension or operations diligence.

### 2. Traditional plugin use cases

**WooCommerce** is the only candidate in the supplied set that is clearly a WordPress plugin as its primary product form. Official findings cover products, orders, payments, shipping, taxes, customers, reporting, marketing, REST API v3 and client libraries. This makes it the natural candidate where So7ob wants a conventional WordPress store or has a WordPress operating model.

Constraints are important: core multi-vendor support was not evidenced; official documentation describes a separately installed marketplace plugin. Arabic/RTL is not verified beyond generic localization documentation. The root license was unavailable during research; the plugin readme declares GPLv3, while GitHub API metadata reports `NOASSERTION`. Each extension, theme and dependency needs its own license and update review.

Shopware, PrestaShop and Magento Open Source are also conventional self-hosted commerce applications, but the supplied evidence does not characterize them as WordPress-style plugins. Their APIs and extension models can support headless or integration use, but should not be conflated with plugin-first deployment.

### 3. Customizable/self-hosted use cases

The strongest candidates for an engineering-led, customizable deployment are:

- **Medusa:** modular Node/TypeScript platform with workflows, commerce modules, REST routes, provider integrations, custom modules/models/endpoints and a customizable admin. PostgreSQL is the core database; Redis may be used for infrastructure. Self-hosting requires Node/PostgreSQL and potentially Redis, admin and storefront components.
- **Vendure:** TypeScript/NestJS framework with Shop/Admin GraphQL APIs, worker/job queue, plugins, channels, locales and replaceable integrations. SQL support includes PostgreSQL, MySQL/MariaDB and SQLite. Self-hosting and plugin work are expected.
- **Sylius:** Symfony/PHP framework with developer control over data model, business logic, checkout and frontend; REST/API Platform and configurable channels/locales. MySQL, MariaDB and PostgreSQL examples are documented. It is a plausible fit where So7ob has Symfony capability, with a moderate-to-high implementation and operations burden.
- **Saleor:** API-only GraphQL backend with Docker/Docker Compose setup, multiple services, separate dashboard/storefront and extension mechanisms. The project itself cautions that its service-oriented architecture may be complex for a small developer or small business.
- **Spree:** self-hostable Rails backend with REST APIs, SDKs, React admin, Seller Panel and optional Next.js storefront. It has strong marketplace evidence, but the database engine was not verified.
- **Bagisto:** modular Laravel platform with documented packages, REST API, Docker/Sail/manual installation and explicit multi-vendor positioning. Its current supplied release evidence is beta, so release suitability and advisory status require confirmation.

**More traditional but still customizable/self-hosted:** Shopware, Magento Open Source and PrestaShop provide substantial modules, themes, APIs and commerce domains, but their supplied setup, version and upgrade evidence indicates meaningful application/server/dependency operations. WooCommerce similarly requires ownership of the WordPress/plugin/theme/extension stack.

## Candidate notes and fit implications

### Saleor
Saleor is the clearest supplied example of an API-only/headless backend: GraphQL is the stated interaction surface, with separate dashboard and storefront projects plus webhooks, apps, metadata, attributes, subscription queries and API extensions. It is a strong candidate for a composable, multichannel proof of concept, but the supplied evidence did not verify the supported database/version, test coverage, first-class multi-vendor behavior or Arabic/RTL. Docker setup includes migrations, optional sample data, admin creation and multiple containers, and the repository cautions that the service-oriented architecture can be complex for a small team. BSD 3-Clause permits broad reuse subject to notices, but dependencies, trademarks and hosted-service terms remain separate diligence items.

### Medusa
Medusa offers the strongest combination of documented modularity and headless customization among the JavaScript/TypeScript candidates: workflows contain business logic, modules expose commerce functionality through REST routes, providers integrate external services, and custom modules/models/endpoints/workflows are supported. PostgreSQL is the core supported datastore; Redis may be used for infrastructure. Its marketplace reference is not enough to conclude that seller tenancy, onboarding, commissions or payouts are built in. MIT applies to the repository boundary, while Enterprise Edition materials require separate licensing. The 2026-09-28 `v2.21.2` release and 2026-10-14 commit indicate activity, but the security-advisory extraction did not establish absence of issues or current exposure.

### Vendure
Vendure is a capable headless TypeScript framework shape: separate Shop and Admin GraphQL APIs, a worker/job queue, SQL database options, and plugins that can extend types, resolvers, entities, integrations, events and worker tasks. Marketplace is described as a use case and a Seller entity is documented, but complete multi-vendor behavior is not established. The security history is a material selection constraint: the supplied advisory evidence lists multiple 2026 high/critical issues, including cross-channel/access-control and API-key privilege issues, while `v3.7.4` reports fixes for two vulnerabilities. The repository states GPLv3 and discusses a plugin exception and commercial Platform, but the exact license file was not read; obtain legal review before deciding on modification, distribution and plugin use.

### Sylius
Sylius is a strong bespoke-commerce option for a Symfony/PHP team. Its supplied documentation describes a headless/API-first REST API built on API Platform, configurable channels/locales/currencies and developer control over the data model, business logic, checkout and frontend. It supports MySQL, MariaDB and PostgreSQL examples. The evidence does not establish multi-vendor Community Edition capability; commercial Sylius Plus material should not be treated as Community Edition evidence. MIT is clear for the repository, but dependencies, plugins and Plus boundaries need review. Multiple 2026 security advisories, including high-severity JWT and Host-header issues, make release-specific patch verification essential.

### Shopware
Shopware Community Edition is a PHP/Symfony/Vue commerce platform with apps/plugins and API-first/headless positioning. It may fit general digital commerce, but the supplied evidence does not establish native marketplace sellers or Arabic/RTL. Community Edition self-hosting and paid/hosted feature boundaries are important constraints. The MIT repository license does not automatically cover extensions, dependencies, trademarks or paid features. Multiple 2026 critical/high advisories were visible in the supplied research; verify the exact patched release and all extensions before deployment.

### Spree Commerce
Spree is the strongest marketplace-oriented candidate in the supplied evidence. Its repository overview describes seller onboarding, per-seller order splitting, commissions, a payout ledger/Stripe Connect and Seller Panel in open-source core, alongside Store/Admin/Seller REST APIs and SDKs. It is self-hostable and supports an optional Next.js storefront. However, the database engine was not verified, Arabic/RTL was not established, and the advisory page shows multiple 2026 vulnerabilities, including high-severity access-control/IDOR issues. The stable `v5.6.1` release and separate `6.0.0.rc3` activity should not be conflated; validate the intended branch and supported security version.

### WooCommerce
WooCommerce is the natural traditional-plugin candidate: a WordPress commerce platform with extensive merchant documentation and a documented REST API v3. It can be evaluated for a WordPress-based store or API-connected frontend, but the supplied research did not establish it as an independently deployed commerce service. Multi-vendor is documented through a separately installed marketplace plugin rather than core evidence. The plugin readme declares GPLv3, while the root license was unavailable and GitHub metadata reported `NOASSERTION`; this is a license-verification item, not a conclusion that reuse is prohibited. Security policy generally focuses support on the latest version, with possible critical fixes backported, so exact-version maintenance is essential.

### Magento Open Source
Magento Open Source has broad REST, SOAP and GraphQL surfaces, a modular PHP architecture, service contracts, themes, attributes and integration mechanisms. It is a serious customizable commerce application, but the supplied setup evidence points to nontrivial operations: release-specific PHP/database/Composer requirements plus search, cache, queue, web-server and other services. No native marketplace capability was evidenced. The exact OSL-3.0 text contains external-deployment implications, and the repository notes that applicable customer ordering terms may supersede OSL for covered files; legal review is mandatory for a hosted or modified deployment. The latest observed release was `2.4.10-alpha1`, and Adobe bulletin APSB26-92 lists material vulnerabilities, so the alpha status and exact patch line are both gating concerns.

### PrestaShop
PrestaShop is a traditional PHP commerce application with product, cart, order, customer, carrier, tax, stock and multistore domains, plus legacy Webservice and newer Admin API surfaces. It is directly relevant to online-store evaluation but not evidenced as a native marketplace platform. Its core/modules licensing is split between OSL-3.0 and AFL-3.0, and bundled dependencies have separate notices. The supplied security history contains multiple High/Critical advisories from 2025–2026. Validate the intended `9.2.0` release, PHP 8.1+ and MySQL-compatible requirements, module compatibility and upgrade process before considering adoption.

### Bagisto
Bagisto combines a Laravel modular architecture, documented REST API package and explicit marketplace and localization claims. The supplied 2.5 branch instructions list `ar` and official localization documentation identifies RTL support for Arabic, Hebrew and other RTL languages; this is the best Arabic/RTL starting signal, but not proof of complete translation or visual/functional correctness. Marketplace capabilities are explicitly described, yet the exact split between core and packages/extensions, and any licensing/pricing boundary, must be confirmed. The latest supplied release is `v2.5.0-beta2`, which materially lowers confidence for immediate selection. Several advisories, including critical/high issues, require release-specific patch verification; no formal security policy was verified.

## Cross-cutting constraints and diligence gates

Before selecting or piloting any candidate, So7ob should require evidence for the following:

1. **Exact release and security baseline:** choose a specific version, check its supported-version policy, map every listed advisory to fixed versions, and audit transitive dependencies. Do not rely on a latest-release label alone; Magento's latest observed release is alpha and Bagisto's is beta, while several candidates have active 2026 advisories.
2. **Arabic/RTL acceptance test:** test catalog, checkout, account, order history, search, emails, admin, seller workflows, themes, PDFs and third-party extensions in Arabic and RTL. Bagisto is the only candidate with explicit supplied RTL-language evidence, and even there completeness is unverified.
3. **Marketplace proof of concept:** test seller onboarding, permissions, catalog ownership, moderation, order splitting, commissions, payouts/refunds, taxes, shipping, returns, reporting and dispute flows. Treat Spree/Bagisto claims as promising evidence to validate, not production proof; treat Medusa/Vendure marketplace references as insufficient until these flows are demonstrated.
4. **Architecture and operations:** document whether So7ob wants a WordPress plugin, a self-hosted application, a composable backend, or a managed service. Measure containers/services, database/search/cache/queue needs, backups, observability, upgrades, disaster recovery and staffing. No supplied finding establishes a hosted SLA or production operating model.
5. **License boundary review:** review repository license, dependencies, themes/plugins/extensions, trademarks, paid/enterprise components and any hosted-service terms. Pay particular attention to Vendure GPLv3/plugin exception/Platform, Magento OSL external deployment, PrestaShop OSL/AFL split, WooCommerce's unresolved root-license retrieval, and Bagisto/Shopware/Medusa extension or enterprise boundaries.
6. **Tests and integration fit:** run the candidate's tests and a So7ob workflow spike. Supplied documentation of test scripts, BDD, E2E harnesses or CI does not establish coverage, passing status or production quality.
7. **Data and version compatibility:** verify database engines and versions where the supplied research marked them unknown or release-specific, especially Saleor, Spree and Magento/PrestaShop/Bagisto release lines.

## Provisional shortlist by evaluation path

These are **starting points for proof of concept, not recommendations to adopt**:

- **GraphQL-first composable backend:** Saleor, then Vendure.
- **Customizable JavaScript/TypeScript commerce:** Medusa, then Vendure.
- **Symfony/PHP bespoke commerce:** Sylius.
- **Marketplace-first investigation:** Spree and Bagisto; validate both before treating either as a platform decision.
- **WordPress/plugin-led store:** WooCommerce.
- **Established traditional PHP commerce application:** Shopware, Magento Open Source or PrestaShop, subject to heavier release/security/operations diligence.

No candidate should be selected from this desk research alone. The next decision should be based on disposable proof-of-concepts, exact-version security and license review, Arabic/RTL acceptance testing, and measured operational effort.
